# Decisions — one line each: choice — reason

- Vite + React + TypeScript — required by the brief (TS preferred); Vite needs no build config.
- React Router — standard client-side routing for the pages (store, product, cart, orders).
- TanStack Query — handles fetching, caching, loading and error states, so components stay small.
- Tailwind — fast to match Eneba's design; colors and font live in one config as tokens.
- Zustand (cart) — tiny global store for cart state across pages, less boilerplate than Redux/Context.
- Laravel (PHP 8.5) — brief asks for PHP; built-in migrations, seeders, validation and transactions mean less custom code.
- REST under /api — simplest to build, test and explain; the brief allows REST or GraphQL.
- Sanctum bearer tokens — Laravel's built-in API auth; tokens avoid cross-domain cookie issues between Vercel and Render.
- Postgres on Neon — free tier that doesn't expire (Render's free Postgres is deleted after 30 days).
- pg_trgm for fuzzy search — typo tolerance inside the DB, no separate search service to host.
- Vercel /api rewrite — frontend calls same-origin /api, so no CORS setup and no hardcoded backend URL in the browser.
- Render (Docker) for backend — free PHP hosting; Docker makes the PHP version explicit. Cold starts of ~30–60 s after idle are accepted.
- Prices in integer cents — avoids float rounding errors in totals.
- Laravel Herd for local PHP — already installed; bundles PHP 8.5, Composer and the Postgres driver.
- Neon branches: `production` (Render) + `dev` (local, auto-delete off) — local `migrate:fresh` can never wipe live data.
- Direct (non-pooled) Neon connection — migrations and a few connections don't need PgBouncer; avoids pooler quirks.
- Local dev server = `php -S -t public` instead of `artisan serve` — Avast deletes Laravel's router script (false positive); the plain built-in server sends unknown paths to index.php anyway.
- Composer via `--prefer-source` + custom CA bundle — Avast intercepts HTTPS and locks downloaded zips; changing antivirus settings is the user's call.
- Dockerfile with `artisan serve` on Render — Linux container has no Avast; simplest way to run PHP on a free tier (shortcut noted in the file).
- One product row per edition (game × platform × region) — matches how Eneba lists keys; filters stay simple WHERE clauses.
- Stock = count of unsold game_keys, no stock column — a counter could drift from the real keys; a count can't.
- products.popularity instead of computing best sellers from orders — there are no orders yet; checkout will bump it later.
- Seeders without Faker, fixed mt_srand seed — Faker is dev-only (missing on Render); same data on every run.
- Seed on every deploy, skip if products exist — Render free tier has no shell to run seeds by hand.
- Placeholder cover images (placehold.co) — no copyright issues with real game art; marked as a shortcut.
- "From" price = cheapest offer with stock, and the price filter matches that same price — an offer with 0 keys can't be bought; filtering on any other price showed cards outside the chosen range (found in the store page check).
- Sold-out products stay listed with price null, sorted last — the brief says browse every product; nulls-last keeps price sorts useful.
- Search = ILIKE partial match OR pg_trgm word_similarity ≥ 0.3 — measured: "wichter"→Witcher scores 0.30, unrelated names ≤ 0.25; plain similarity() is too low for long names (0.11).
- One "unsold key" definition (GameKey::scopeUnsold) used by stock, price and filters — Day 3 checkout changes one line and everything follows.
- API Resources shape the JSON; key codes are $hidden on the model — DB columns aren't the public API, and codes can't leak by accident.
- Price params in cents (min_price=500) — same unit as the DB and responses; frontend converts.
- Stable pagination: always tie-break ORDER BY id — equal sort values could otherwise jump between pages.
- Tests on a separate Neon "test" branch, skipped unless .env.testing has a DB_URL — tests wipe their DB; Laravel would otherwise fall back to .env (dev).
- Metropolis font via @fontsource/metropolis — Eneba's font; self-hosted from npm, no Google Fonts (it isn't there) or CDN dependency.
- Search results live on the store page (/store?q=…), no separate search page — same as Eneba; one page handles search + filters.
- Featured offer = cheapest offer in stock — Eneba features a "Verified by Eneba" seller; we have no verification concept.
- Seller rating labels: ≥9.8 Superb, ≥9.5 Excellent, ≥9.0 Very good, else Good — matches Eneba's examples (9.91 Superb, 9.63 Excellent).
- "Buy now" shown but disabled until the cart exists (Day 3) — layout stays final; graders see where buying happens.
- 404 from the API isn't retried (TanStack retries other errors 3×) — a missing product won't appear on retry; shows "Product not found" immediately.
- Homepage API: /api/homepage lists blocks (type, title, endpoint) by position; each block type has its own endpoint + source — the brief's "each block from its own backend source"; reordering is a data change, no deploy.
- Frontend block map (type → component); unknown types are skipped — a new home_blocks row can't break the page.
- Rolling deals: an ended deal's end moves forward by whole weeks (Deal::currentEnd) — seeded demo deals would all expire before grading; marked as a shortcut.
- Best sellers = top 12 by popularity among in-stock products — a best seller you can't buy looks broken.
- All homepage endpoints return {"data": [...]} — same shape as Laravel resources, one parsing path in the frontend.
- Data fixes go in migrations, not re-seeds (e.g. lighter cover color) — the live DB only runs migrations on deploy; down() reverses it.
- Header matches eneba.com measurements: 1200 px content + 20 px padding, 20 px top padding, 550×57 search box (transparent, light outline, 19 px/800 text), 50 px nav band (black 25 %) with platform links from /api/filters; footer black 70 % with 20/50 px padding and 12 px #DCD8E6 links (re-measured at 1440 px; an earlier "dark-filled search box" guess was wrong).
- Footer "For the Eneba internship task" — makes clear it's an assignment, not Eneba's site.
- :focus-visible yellow outline everywhere — keyboard users can see focus on purple; mouse clicks don't get an outline.
- Loading skeletons skipped (parked in WANT_TO_FIX #4) — nice-to-have; protects Day 3 time.
- Sanctum bearer tokens, 7-day expiry; logout revokes only the current token — tokens are stored hashed; other devices stay logged in.
- Login error is the same for unknown email and wrong password — doesn't reveal which emails have accounts.
- Register/login rate limit 6/min per IP + trustProxies('*') — behind Vercel + Render every request looks like the proxy's IP; trusting X-Forwarded-For gives each visitor their own limit (spoofable: noted shortcut).
- Token in localStorage via Zustand persist — survives refresh; readable by injected scripts (acceptable for a demo, noted in README).
- api() clears the session on any 401 — an expired/revoked token logs you out locally instead of failing silently.
- Post-login redirect only to local paths (safeNext) — blocks open redirects like ?next=//evil.com.
- Demo account demo@eneba-market.test (password in README) via an update-or-create seeder that runs on every deploy — graders can log in without registering.
- Checkout = one DB transaction: lock keys (FOR UPDATE SKIP LOCKED) → order + items → simulated charge; any failure (stock, declined card) rolls back everything — no half-orders, no stuck reservations. Verified with two real DB sessions: B got the next key in 0.43 s while A held the first.
- game_keys.order_item_id is UNIQUE — even a logic bug can't attach one key to two order items; the DB refuses.
- One order_items row per key; price_cents copied at purchase — order history stays correct if prices change later.
- No order status column — single-step payment means only paid orders exist.
- Prices come from the DB at checkout; the browser sends only offer ids + quantities — a tampered request can't change what's charged.
- Only the card's last 4 digits leave the browser (enough to simulate a decline on ...0002); card inputs autocomplete=off + "never enter a real card" notice — a real card typed by mistake never reaches the server.
- Cart in the browser (Zustand persist), max 10 per line, capped at the stock seen when added — guests can fill it; the server re-checks stock at checkout.
- "Buy now" adds that seller's offer and opens /cart (Eneba jumps to checkout) — lets the buyer review first.
- Order history queries through $request->user()->orders() — other users' orders are never fetched, so there's no ownership check to forget.
- One /orders page, no detail page — each order card already shows its items and keys.
- Keys hidden until "Reveal" (UI only; the owner's API response contains the codes) — like Eneba, protects against shoulder-surfing.
- Orders query keyed by user id — two people on one browser never see each other's cached keys.
- Order::FOR_RESOURCE lists the eager-loaded relations once — checkout and order history can't drift apart, no N+1 queries.
- No pagination on /api/orders (shortcut) — demo users have a handful of orders; paginate() when lists grow.
- Real covers: Steam's official 600x900 library art for 23 of 28 games (app ids looked up via Steam's store search API, each URL checked to return the right game's JPEG); credited "Game images © their publishers, via Steam" in the footer. Linked, not downloaded or rehosted.
- Zelda, Mario Kart, Minecraft (not on Steam) and FC 26, FM 26 (no public portrait URL) keep the styled title placeholder — 8 of 70 products.
- Covers applied by a data migration (use_steam_covers), seeder updated for fresh DBs — same pattern as the cover-color fix; the live DB updates on deploy, down() restores placeholders.
- <Cover> component swaps a failed image to the title placeholder once — Steam can change URLs; cards never show a broken-image icon.
- Cards stay 3:4 (Eneba's shape); 2:3 Steam covers are centre-cropped (~11 % top/bottom).
- Card buttons add the offer behind the card's "From" price (Product::cheapestOffer, Laravel one-of-many: cheapest in-stock, ties → lowest id) — card price = cart price; sold-out cards get no buttons.
- forCard() scope = everything a card needs (platform, region, price, cheapest offer + seller + stock) — one place for the store, deals and best-seller queries; one extra query per page, not per card.
- Card = box with two links + a separate button bar (no buttons inside links: invalid HTML, bad for screen readers); image link removed from tab order to avoid a duplicate stop.
- Buttons over the cover's bottom edge, fade in on hover/keyboard focus, always shown on touch screens (hover: none) — no layout jump, no empty strip.
- "Add to cart" checks the quantity really increased ("Max in cart" at the stock/10 cap) instead of always claiming "Added".
- Header logo: own yellow rounded mark with a purple "e" (logo.svg), 52 px, bigger than the 22 px word mark — the purple favicon square vanished on the purple header; favicon stays purple (works on light browser tabs).
- Banners: Steam wide hero art via data migration (use_banner_art) — Elden Ring, Cyberpunk 2077 for "Steam games", Hollow Knight (sold on Nintendo here) for "Nintendo eShop"; hero art has no logo text, so the overlay shows title + subtitle again; <Cover fallback> swaps a failed banner to a wide placeholder.
- Cart re-checks the server on open and window focus (GET /api/offers?ids=, max 20 numeric ids) — quantities above stock are lowered with a notice, sold-out lines stay visible and block checkout/Pay until removed, prices follow the server (replaces the "price snapshot" shortcut). The checkout transaction still re-checks everything.
- Loading skeletons in the real layouts (store grid, homepage banner + rows, product page, orders); grids share STORE_GRID/ROW_GRID with the real content so nothing jumps; motion-safe pulse; role=status "Loading" for screen readers. Search dropdown keeps its "Searching…" text.
- Filter counts: /api/products returns `facets` (one request, always in sync with the list); each group counts with every filter except its own (ticking Steam keeps GOG's count meaningful), via two grouped COUNT queries on the foreign key; 0-count options greyed + disabled unless already ticked (so they can be unticked).
- AGENTS.md is a two-line pointer to CLAUDE.md — other agents (Codex, Cursor, …) read AGENTS.md by convention; one source of rules, no copy to drift.
- Card hover like eneba.com: the text panel slides up 92 px over the cover and reveals stacked full-width Add to cart + View offers (outlined link to the product page, as on Eneba; replaced the card's Buy now); a matching -92 px margin + overflow-hidden keeps card height fixed so the grid never jumps; touch screens show the buttons under the price; reduce-motion skips the slide.
